An investigation into language models & cause and effect

Right answer.
Right reason?

A language model can get the answer right and still misunderstand the problem. It can also be marked wrong when the answer key is mistaken.

This project asked what causal reasoning tests actually measure, and what changes when we check the question, the explanation, and the underlying rules separately.

The question behind it all

When a model says “yes”, what evidence makes that answer trustworthy?

01 / The starting point

From scores to explanations.

The starting point was CLadder, a benchmark of short, artificial stories about cause and effect. Each story supplies rules or probabilities and asks a yes/no question. Some ask what tends to happen; others ask what happens when we change something, or what would have happened under a different action.

The retained version contains 10,112 questions. Earlier model runs produced 91,272 saved responses across 12 conditions. Those records made it possible to compare short answers with a six-step causal reasoning prompt, inspect explanations, and test symbolic checking.

A high score initially looks reassuring. But it leaves several questions unanswered. Was the answer key right? Did the story contain enough information? Did the explanation preserve the rules? And did a checker verify the explanation or only a formula extracted from it?

Source: supplied research report, pp. 2, 5–10. Archive conditions include repeated questions under different prompts; responses are not independent questions.

02 / What emerged

Five things worth keeping separate.

Matching an answer key

Useful for comparison, but a mistaken key can reverse who looks correct. The audit supports 46 specific label corrections; it does not certify the rest of the benchmark.

See the benchmark audit

Having enough information

A story can define a cause-and-effect question without fixing its answer. Some mediation questions leave the effect size unknown while still fixing its sign; others leave even the sign open.

See the information audit

Producing an accepted formula

A checker can accept a correct-looking expression even when it came from an unrelated explanation. Formula acceptance and explanation validity answer different questions.

See the transplant tests

Preserving the actual operation

Seeing a variable equal zero differs from forcing it to zero. Checking an outcome differs from checking whether an action changed it. Small wording differences can specify different mathematical tasks.

Understand the operations

Explaining why a model fails

Several candidate explanations failed their planned tests. A vivid example can reveal a visible mistake, but it does not identify the model’s hidden process or explain every error.

03 / A concrete example

One changed rule. A different answer.

In one CLadder story, a manager and a director can each cause an employee to be fired. The rules shown to the model differ from the rules used by the reference solution.

If we keep the displayed rules and apply the requested intervention, the answer is No. The stored key says Yes. A model following the story can therefore lose a point for doing the right computation.

This was systematic: 37 of 158 inspected DiamondCut questions showed this mechanism discrepancy. Nine further numerical discrepancies survived a rounding-aware audit.

05 / A useful intervention

Give the model the relevant truth values.

In small, completely specified Boolean worlds, the model sometimes failed even when it only needed to read a supplied table. Giving it the truth value of the actual question helped more than merely listing all intermediate calculations.

Even the strongest condition in this study leaves many errors. Later tests found that removing irrelevant input columns helped on a smaller, simpler task. Shortening context and the proposed multiplicity explanation did not pass their planned tests.

06 / Where the project lands

Trust needs more than a score.

Check the question. Preserve the rules. Verify the answer and its support.

The strongest outcome of this work is a clearer measurement approach. It shows where an answer key is unreliable, where a prompt leaves multiple compatible answers, where formal checking is too narrow, and where an explanation visibly contradicts the task.

It also records what did not work: weak predictive transfer, inconclusive prompt repairs, failed neural interventions, and judge campaigns that failed quality checks. Those results help close the project honestly, without turning every promising example into a general claim.

The experiments concern specified artificial worlds and recorded language-model responses. They do not establish general causal discovery, reliable real-world decision making, or a complete account of a model’s internal reasoning.
